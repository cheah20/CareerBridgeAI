The formatting shortcut in v5

ResumeAtlas text is stored lowercased, without punctuation and without common words. Kaggle text is ordinary prose. Prose-format resumes appear in only 23 of the 45 categories; the other 22 (Data Science, Python Developer, Civil Engineer, Testing and more) never appear as prose.

v5 learned that link: ordinary prose meant "one of the 23 Kaggle categories". Real resumes are prose, so a Malaysian data analyst could never be classed as Data Science. The public test set has the same mix of formats, so its 88.2% did not reveal the problem.

Text share in the training data

FormatShareCategories
Lowercase, no punctuation, no stop words (ResumeAtlas)83%43
Ordinary prose (Kaggle)17%23

Fix (v6 onward): every text, in training and in prediction, is normalised to one form (lowercase, punctuation removed, NLTK stop words removed). 297 of 300 ResumeAtlas samples are unchanged by it, so only the Kaggle prose is converted.

Synthetic Malaysian resumes

No public dataset of Malaysian resumes exists, so two kinds of synthetic resumes were generated with the LLM and compared. The 58 real CVs were used only as style references and were never trained on.

Rough set · used in v7

  • 45 resumes, one per category, written in a single LLM call each
  • Plain text, short (120–650 words), similar layout throughout
  • No reference template, no rendering
  • Added to training 10× (450 rows)

Template-based set · used in v8

  • 158 resumes, one for every role in the CareerBridge catalogue
  • A random profile per person drawn in code: level, 1–4 jobs, part-time (42), freelance (35), internships, career gaps (12%), career switches, Malaysia/Singapore, languages matching background
  • The LLM wrote each profile up in one of six layouts modelled on the reference material: the Malaysian CV pack, the JobStreet template, a career-guide CV, student, plain Word and two-column
  • Each resume was typeset as a real file (65 PDF, 81 Word, 12 JPG) and read back with the app's own extractor, including OCR
  • 126 resumes map to the 45 categories; added to training 4× (504 rows)

Reading the results

  • On the public test set the three new models are within one point of each other; only the real CVs separate them.
  • Template-based synthetic data (v8) improved every measure on real CVs; rough synthetic data (v7) did not.
  • v5's public-test lead disappears on real resumes.

Limits

  • Small sample: on category top-1, v8 and v2 differ by 6 CVs (38 vs 32 of 45).
  • 13 real CVs (8 administrative, advertising, compliance, hospitality, oil and gas, supply chain) have no matching category among the 45, which caps field top-1.
  • The CV pack shares one template, so it does not cover every Malaysian resume style.

Issues found and fixed in Part 2

Formatting shortcut

Described above. Fixed by normalising all text to one form in training and prediction.

Memory growth during prediction

Scoring many resumes of different lengths made ONNX Runtime reserve memory for every input size; one comparison run reached 14 GB. The memory arena is now off, batches are smaller and only one model is loaded at a time. This also protects the backend, where uploaded resumes vary in length.

Incomplete LLM answers

8 of 158 synthetic resumes failed because the reasoning model used its whole token budget before answering. They were regenerated with a larger budget so every catalogue role is covered.

Job-run chaining

A script that waited for one run to finish detected its own command line and waited forever. Process checks now match only the training process itself.

Hyperparameters

  • Base model: microsoft/deberta-v3-small (142M parameters)
  • 4 epochs, learning rate 3e-5, weight decay 0.01, linear schedule with 10% warm-up (253 steps)
  • Batch 8 per step × 2 accumulation = effective batch 16; 2,536 optimiser steps
  • bf16 mixed precision, fp32 master weights
  • Max 512 tokens; long resumes keep the first 382 and last 128 tokens
  • Best epoch chosen on validation macro F1

Hardware and software

  • NVIDIA RTX 4070 Laptop GPU, 8 GB, driver 581.15; AMD Ryzen 9 8945H; WSL2 Ubuntu 20.04
  • Training env: Python 3.12, PyTorch 2.14.1 (CUDA 13.0), transformers 5.20.1, datasets 5.1.0, onnxruntime 1.31.0, onnx 1.23.2
  • App env: Python 3.14, onnxruntime 1.31.0, tokenizers 0.23.3 (no PyTorch)
  • Training env is separate from the app and from ROS Noetic

Issues found and how they were fixed

VRAM overflow made training about 4× slower

With batch 16, the 8 GB of VRAM filled and Windows moved about 0.6 GB into shared system memory. The GPU waited on memory transfers and drew only 38 W. Batch 8 with 2 accumulation steps gives the same effective batch and the same result, but uses 6.9 GB and runs at about 97 steps per minute instead of under 25.

int8 quantisation cost too much accuracy

Quantising the whole network (v3) dropped test accuracy from 0.872 to 0.784. Quantising only the MatMul layers still matched PyTorch on just 86.6% of validation resumes. DeBERTa is sensitive to dynamic int8 quantisation, so v5 ships as fp32 ONNX, which matches PyTorch on 1,127 of 1,127 validation resumes.

Lost weights in run A

The first script deleted the PyTorch checkpoint after exporting, so the bad int8 file could not be re-exported. The script now keeps the trained model in models/transformer-candidate/pytorch/ and removes only the epoch checkpoints.

No visible progress

The first runs filtered out the progress bar. The script now writes step, percentage, speed, time left and loss to data/training_runs/progress.log, and training/watch_progress.sh shows it live with GPU temperature and a safety level.

Search for Malaysian resume data

A search of Kaggle, Hugging Face, GitHub and the Malaysian open-data portal found no public dataset of Malaysian resumes. Public resume sets (ResumeAtlas, Kaggle Resume Dataset and smaller Hugging Face sets) have no country field. What exists:

  • Nemotron-Personas Malaysia (YTL AI Labs and NVIDIA, September 2026): 1.35 million synthetic personas with occupation, region, age and ethnicity, generated from official Malaysian statistics. Reported as CC BY 4.0. These are personas, not resumes, but could seed synthetic Malaysian test resumes.
  • data.gov.my: aggregate labour statistics (registrants, vacancies, placements), useful context but not resume text.
  • Commercial JobStreet feeds and scrapers: job postings rather than resumes; paid, and scraping conflicts with JobStreet's terms. Not used.

Conclusion: a small, consented set of 30–50 real Malaysian resumes, with personal details removed, remains the most credible way to check v5 on local resumes. It is needed for testing, not for retraining.

Data. ResumeAtlas (MIT) and Kaggle Resume Dataset (CC0): 14,081 resumes after de-duplication, 45 categories, 11,264 train / 2,817 test. Run B used 10,137 for training and 1,127 for validation. All data and model files stay on the developer's machine and are not uploaded to Supabase or Git.
